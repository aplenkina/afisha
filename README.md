# afisha

Веб-афиша развлекательных событий Беларуси. Подробный план, этапы и сроки: [app/PLAN.md](app/PLAN.md).

- `app/` — сайт и админка на Symfony (PHP, Twig, EasyAdmin), PostgreSQL.
- `app-go/` — сборщики событий на Go: раз в сутки забирают события с сайтов-источников и кладут их в базу черновиками.
- `docker/`, `docker-compose.yml` — окружение разработки.

## Запуск после клонирования

В репозитории нет зависимостей и секретов, их нужно создать на своей машине.

### 1. Секреты

Создайте каталог `docker/secrets/` (он в `.gitignore`) с файлами, в каждом только значение:

| Файл | Что внутри |
|---|---|
| `POSTGRES_USER.txt` | пользователь базы |
| `POSTGRES_PASSWORD.txt` | пароль базы |
| `TELEGRAM_BOT_TOKEN.txt` | токен бота от `@BotFather` |
| `TELEGRAM_CHAT_ID.txt` | id чата, куда бот присылает сводки |
| `APP_SECRET.txt` | секретный ключ приложения, например `openssl rand -hex 16` |

### 2. Настройки Symfony

`app/.env` в репозитории нет (он в `.gitignore`), создайте его из примера:

```bash
cp app/.env.example app/.env
```

Впишите в нём `DATABASE_USER` и `DATABASE_PASSWORD` **те же**, что в `docker/secrets/POSTGRES_USER.txt` и `POSTGRES_PASSWORD.txt`. Остальные значения (хост, порт и имя базы) уже подходят для Docker.
Другие `.env`-файлы не нужны: `docker-compose.yml` в корневом `.env` не нуждается, а `app/.env.dev` и `app/.env.test` уже в репозитории.

### 3. Контейнеры

```bash
docker compose up -d --build
```

| Сервис | Адрес |
|---|---|
| сайт и админка (`app`) | http://127.0.0.1:1810, админка `/admin` |
| PostgreSQL | `127.0.0.1:1811` |
| сборщик (`app-go`), `/health` | http://127.0.0.1:1812 |

### 4. PHP-зависимости (`app/vendor`)

Каталог `app/vendor` в git не лежит (около 80 МБ), он целиком восстанавливается из `app/composer.lock`.
Docker-образ сам зависимости не ставит: он монтирует `./app` с вашего диска, поэтому **без этого шага приложение не запустится**.

```bash
docker compose exec app composer install
```

### 5. Миграции базы

```bash
docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction
```

## Сборщики событий

- Источники и их настройки (страницы со списком событий, соответствие разделов сайта категориям) заводятся в админке: `/admin/source`. Новому источнику с разметкой `schema.org/Event` код не нужен.
- Выключить источник можно переключателем «Собирать события». Итог последнего запуска виден в том же списке.
- Запуск по расписанию: раз в сутки в 04:00 по Минску (`COLLECT_AT=ЧЧ:ММ` меняет время). Пропущенный запуск догоняется.
- Собранные события появляются **черновиками**. На сайте видны только опубликованные: публикуйте их в `/admin/event`.
- После каждого запуска в Telegram приходит сводка: сколько собрано, добавлено и обновлено, что пропущено и почему.

Ручной запуск и проверка Telegram:

```bash
docker compose exec app-go ./main -once
docker compose exec app-go ./main -notify-test
```

Сборщик читает `robots.txt` источника и не открывает закрытые страницы. Забирает только факты (название, дата, место, цена, ссылка), тексты и фото целиком не копирует.

## Тесты

```bash
docker compose exec app php bin/phpunit
cd app-go && go test ./...
```

## Часовой пояс

В базе время хранится в UTC (`timestamptz`), сайт и админка показывают его по Минску (`Europe/Minsk`). Если смотрите данные напрямую в SQL-клиенте, добавляйте `at time zone 'Europe/Minsk'`.
