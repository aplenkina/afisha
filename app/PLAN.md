# План проекта: афиша развлекательных мероприятий РБ

## Кратко
Веб-афиша развлекательных событий по всей Беларуси:
- категории и разделы;
- подробные фильтры;
- интерактивная карта;
- карточка события со ссылкой на билеты или источник.

События собираются автоматически с сайтов площадок, добавляются вручную через админку и приходят через форму «предложить событие» с модерацией. Подборки событий автоматически публикуются в Telegram-канале.

**Команда и время:** ты одна, 10–12 ч/нед. На расчёты беру 11 ч/нед.

**Стек:**
- **Symfony 7 + Twig + Symfony UX (Turbo/Stimulus).** Страницы отдаются готовыми с сервера, это важно для поискового трафика. Фильтры при этом работают без перезагрузки страницы.
- **EasyAdmin** для админки: экономит 15–20 часов по сравнению с самописной.
- **PostgreSQL.**
- **Go** для сборщиков событий. Они пишут в таблицу-черновик, публикация проходит через модерацию.
- **Leaflet** и бесплатные тайлы для карты.
- **Docker** на одном VPS.

**Ориентировочный срок до MVP:** 12 недель, запуск ~20 декабря. Работа оценена в ~116 ч, ещё ~30 ч запаса (около 25%). Из запаса ~16 ч заложено внутри этапов, остальное — резерв 21–31.12.

**Допущения:**
- Старт с Минска и областных центров. Остальные города появятся по мере того, как будут находиться источники.
- Регистрации пользователей в MVP нет.
- Сайт только на русском языке.
- Сборщики забирают только факты: название, дату, место, цену и ссылку. Тексты и фото целиком не копируем, чтобы не нарушать авторские права.

## Этапы

### Этап 1. Скелет, админка, дизайн — 2 недели
**Цель:** сайт работает на домене, события можно заводить через админку.

Задачи:
- [ ] Разобрать 8–10 источников событий: есть ли у них API, RSS или структурированная разметка, как часто обновляются. Выбрать 3 источника для сборщиков — ~3 ч
- [ ] Модель данных: событие, категория, площадка (город, адрес, координаты), признаки для фильтров (платно/бесплатно, однодневное, спорт, групповое/индивидуальное) — ~3 ч
- [ ] Скелет проекта на Symfony, PostgreSQL, Docker, деплой на VPS, домен и HTTPS — ~6 ч
- [ ] EasyAdmin: создание и редактирование событий, категорий и площадок — ~4 ч
- [ ] Дизайн: подборка референсов, главная, список и карточка в Figma. Отдать ли главную дизайнеру, решаем здесь — ~6 ч

**Критерии готовности:**
- Сайт открывается по своему домену через HTTPS.
- Событие, заведённое в админке, появляется на странице сайта (пусть пока без дизайна).
- Макеты главной, списка и карточки готовы.

### Этап 2. Сборщики событий — 3 недели
Этот этап идёт рано, потому что он самый рискованный: неизвестно, насколько удобно устроены источники. Об этом лучше узнать в октябре, а не в декабре.

**Цель:** события сами каждый день попадают в очередь на модерацию.

Задачи:
- [x] Каркас сервиса на Go: запуск по расписанию, логи, запись в таблицу-черновик — ~6 ч (черновики пишутся в `event` со статусом `draft`)
- [ ] Три сборщика для выбранных источников, каждый с тестами на сохранённых страницах — ~12 ч
- [ ] Перевод адресов в координаты через Nominatim с кэшем по площадкам — ~3 ч
- [ ] Защита от дублей по названию, дате и площадке — ~4 ч
- [ ] Очередь модерации в админке: «опубликовать», «отклонить», «объединить с существующим» — ~5 ч

**Критерии готовности:**
- Сборщики запускаются раз в сутки без участия человека.
- Опубликовано 100+ реальных событий на ближайший месяц.
- Повторный запуск сборщика не создаёт дублей.
- Если источник вернул 0 событий, приходит уведомление, а не тишина.

### Этап 3. Каталог и фильтры — 3 недели
**Цель:** основной сценарий работает — найти событие и перейти к билетам.

Задачи:
- [ ] Вёрстка главной, списка и карточки по макетам, адаптив под телефон — ~12 ч
- [ ] Фильтры: категория, город, даты, платно/бесплатно, однодневные, спорт, групповые/индивидуальные — ~8 ч
- [ ] Страницы категорий и городов с понятными адресами, например `/minsk/koncerty` — ~4 ч
- [ ] Карточка события: время, место, цена, кнопка «Купить билет» или «Источник» — ~3 ч
- [ ] Прошедшие события автоматически скрываются, тесты на фильтры — ~3 ч

**Критерии готовности:**
- С телефона можно за 3 действия найти, например, бесплатные события в Гродно на выходные.
- У каждой комбинации «город + категория» свой адрес, и эта ссылка открывает ту же выборку.
- Прошедшие события не показываются.

### Этап 4. Карта и форма «предложить событие» — 2 недели
**Цель:** события видны на карте, организаторы могут прислать своё событие.

Задачи:
- [ ] Карта на Leaflet: точки событий по текущим фильтрам, группировка близких точек — ~8 ч
- [ ] Выбор локации на карте или кнопка «рядом со мной» — ~3 ч
- [ ] Форма «предложить событие» с защитой от спама, заявки попадают в очередь модерации — ~5 ч
- [ ] Уведомление тебе в Telegram о новой заявке — ~2 ч

**Критерии готовности:**
- Карта показывает события с учётом выбранных фильтров, клик по точке открывает карточку.
- Заявка из формы появляется в админке и после одобрения видна на сайте.

### Этап 5. Telegram-канал, SEO, запуск — 2 недели
**Цель:** сайт публичный, его находят в поиске, канал живёт сам.

Задачи:
- [ ] Бот публикует в канал подборку «Куда сходить на выходные» по расписанию — ~5 ч
- [ ] SEO: заголовки и описания страниц, sitemap.xml, разметка событий schema.org/Event, картинки для превью ссылок — ~5 ч
- [ ] Яндекс Метрика, ежедневные бэкапы базы, уведомления об ошибках — ~3 ч
- [ ] Показать сайт 5–10 знакомым и поправить то, что им мешало — ~3 ч

**Критерии готовности:**
- В пятницу канал сам публикует подборку без твоего участия.
- sitemap отправлен в Яндекс Вебмастер и Google Search Console, первые страницы проиндексированы.
- Знакомые находят нужное событие без подсказок.

## Риски
| Риск | Вероятность | Влияние | Что делать |
|------|-------------|---------|------------|
| Источник меняет вёрстку или запрещает сбор | высокая | сборщик перестаёт работать | Начинать с источников с API, RSS или разметкой schema.org. Держать тесты на сохранённых страницах и уведомление «0 событий за сутки». Брать только факты и ставить ссылку на источник |
| Дубли одного события из разных источников | высокая | каталог выглядит неряшливо | Автоматическая проверка на дубли и кнопка «объединить» в админке |
| Не успеваем к Новому году | средняя | запуск сдвигается | Список «что урезать» выше, контрольная точка 22.11 |
| Мало событий в регионах | средняя | в регионах пустые страницы | Старт с Минска и областных центров, ручное добавление, форма для организаторов |
| Неточные координаты площадок | средняя | точка на карте не там | Справочник площадок с ручной правкой координат в админке |
| Модерация отнимает много времени | средняя | не остаётся времени на разработку | Автопубликация для проверенных источников, модерация только для новых |
| Спам через форму | средняя | мусор в очереди модерации | Скрытое поле-ловушка против ботов, лимит заявок, капча при необходимости |
| Требования законодательства РБ (где размещать сайт, персональные данные, реклама) | низкая сейчас | важно перед личным кабинетом и монетизацией | Проверить до запуска личного кабинета и платного продвижения |
| Усталость от долгой работы в одиночку | средняя | проект встаёт | После каждого этапа есть результат, который можно показать. Показывай его знакомым |

## Что после MVP
- Личный кабинет организаторов: добавление и редактирование своих событий.
- Платное продвижение событий: закрепление вверху, выделение, баннеры.
- Избранное, напоминания о событии, подписка на категории.
- Больше источников и городов.
- Установка сайта на телефон как приложения (PWA), позже, возможно, мобильное приложение.
- Персональные рекомендации.
